# Five Projects from the First AI Bootcamp Demo Day

On December 15, I hosted Demo Day for the first iteration of the AI Bootcamp. Four students and I presented projects built over the previous couple of months. The goal was to move past isolated prompts and show complete systems that could work with databases, external tools, and untidy real-world data.

I started with a reference project of my own: an agent that works with a simple to-do list application. Lovable helped me prototype the frontend, and FastAPI provided the Python backend. The agent did not need RAG or a knowledge base. I gave the model the backend’s OpenAPI specification so it could create tools for retrieving tasks and marking them complete. I used Logfire to see the whole session, including which tools were called and what each interaction cost. Eighteen pytest tests checked scenarios such as choosing the right tool for a question about today’s tasks.

Scott DeGeest presented a different kind of problem. His Cybersecurity Disclosure Agent helps supply-chain professionals find out whether a company has reported a breach or ransomware incident to the SEC. The input files were often XML or PDF, and valid and invalid XML required different handling. After conversion, the data was indexed in Elasticsearch. Scott also had to represent corporate relationships: the agent needed to understand that Change Healthcare is connected to United Health Group. Token monitoring kept costs and context limits visible.

Carlos Pumar-Frohberg built a User Satisfaction Analyst around Stack Exchange discussions about user interfaces. He wanted to find patterns in frustration. A Docker pipeline fetched the data and stored it in MongoDB for unstructured content and Neo4j for relationships. An orchestrator routed questions about “what” or “how” to a MongoDB agent and relationship questions to a Cipher agent that translated natural language into graph queries. Carlos noticed that the orchestrator often called both agents anyway, as a safety measure.

Vancesca Dinh’s Habit Builder used the Huberman Lab podcast and medical publications to help people think about goals and the reasons behind them. Her pipeline downloaded RSS feeds, transcribed audio with Faster Whisper, and stored embeddings in Qdrant. She added a tool that rewrote a user’s query three ways to improve retrieval, with Logfire for logging and Pydantic for structure. Her demo also exposed a missing boundary: when asked, the agent would draw a cute pig or translate text into Romanian. Guardrails were necessary because obedience alone did not define the intended task.

Asia Amodeo could not attend, so I presented her intelligent email agent. It uses the Gmail API to fetch messages, indexes them in Elasticsearch, and exposes a Streamlit chat interface. At that point it focused on fetching and reading emails, but it addressed the practical problem of email fatigue by helping users find a message or identify what mattered that day.

The projects looked different, but each connected a model to a particular source of data and a set of actions. That was the point of the event: reliable agent work involved data formats, routing, tests, monitoring, and boundaries as much as it involved prompts.
