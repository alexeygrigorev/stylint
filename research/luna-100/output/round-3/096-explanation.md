# The AI Dev Tools Course Follows a Lifecycle

The AI Dev Tools Zoomcamp uses one project to teach a complete development lifecycle. Each module leaves a more complete system than the previous one. Students first learn how to direct an agent, then build and deploy an application, operate it, and finally extend the agent workflow.

Module 1 covers specifications, context, loops, and roles. Students turn a vague idea into a document and backlog. They store project rules in durable context, then separate product management from implementation and QA. Checkable conditions show when a loop should continue.

Module 2 applies that process to a local full-stack app. Students build the frontend, define OpenAPI, and implement the backend.

They add SQLite and test behavior, then compare the implementation with the specification. A generated implementation isn't accepted because it looks plausible. Students test the behavior that matters.

Module 3 covers the seams between components. Students add integration and end-to-end tests, switch to Postgres, containerize the application, and run checks in CI. Deployment turns the local project into a public service. A documented rollback path is part of the result.

Module 4 adds operating discipline. Students deploy every change to development, then promote a tested version to production.

They collect metrics, logs, and traces with OpenTelemetry and display them in Grafana. Alerts represent sustained user impact.

An AI agent can investigate a bounded evidence packet while code enforces permissions and allowed actions. Security audits and incident records complete the operational context. The course connects this work to the same application, instead of teaching operations as an isolated command.

In the fifth module, I teach coding-agent capabilities through instructions and MCP, then add reusable skills and hooks.

It also covers specialized subagents, plugins, and custom agents.

Students document permissions, guardrails, and the way a specialist fits into the project.

The course is free and can be followed independently, while a live cohort adds shared structure:

- deadlines and peer review
- office hours and a leaderboard
- certificates

The final project demonstrates a frontend and backend with an API specification.

It also needs:

- persistent storage and automated tests
- containers and a public deployment
- clear setup instructions

The project also explains how AI contributed and how the student reviewed the result. The course platform handles deadlines and submissions, while GitHub holds materials.

Slack supports questions, and the FAQ collects previous answers. This separation gives each activity a place while keeping the same application at the center.
